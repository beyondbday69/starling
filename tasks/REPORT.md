## Design decisions to review

- `variant` is an opaque `u16` block id. Task 1 has no engine dependency, so the mapping from
  Horizon/Vanilla log block ids to these numbers belongs to the adapter task (Task 4). No
  Horizon API name is used or invented here.
- A log neighbour must match the cut log's `variant`, as the task says. Species is taken from
  the cut log.
- Counting leaves uses the natural-leaf blob reachable from the logs (max 6 blocks from the
  nearest log, at most 4096 leaves) rather than only directly adjacent ones. Player-placed
  (`persistent: true`) leaves are neither counted nor walked through, and a leaf must have the
  tree's species to count. This is what keeps a wooden house or a log pile out.
- Nether fungus: any `WartBlock` counts, regardless of its variant, and wart blocks are
  returned in `ScannedTree::leaves` because the render/fall step has to move the whole cap.
- Mangrove: `MangroveRoot` bridges two logs for mangrove trees only, one root block deep.
- Cherry: branches connect through the normal diagonal log rule; its leaves are collected by
  the same natural-leaf rule. No extra cherry-only rule beyond that is implemented.
- `scan_tree_with_cuts` is an addition to the listed surface. Without it a single
  `scan_tree(cut_pos)` call has no way to know whether the other three logs of a 2x2 base were
  cut, so `IncompleteTwoByTwo` would be unreachable. `scan_tree` keeps the exact signature the
  task specifies.

## Fall-time decision (`fall_speed`)

`fall_speed` scales **simulated time**, not angular acceleration: each real second advances
the fall by `fall_speed` simulated seconds. That is what the concept's "1.5x speed" column
means, and it reproduces its table. Verified before coding with the same integrator
(semi-implicit Euler, 1/120 s substep, start at 3°):

| L | realistic | 1.5x simulated | concept table |
| --- | --- | --- | --- |
| 5 | 2.417 s | 1.617 s | 1.6 s |
| 10 | 3.433 s | 2.283 s | 2.3 s |
| 20 | 4.850 s | 3.233 s | 3.2 s |
| 30 | 5.933 s | 3.950 s | 4.0 s |

Scaling `alpha` by `fall_speed` would only divide times by `sqrt(1.5) ≈ 1.225` and miss the
table (e.g. 1.97 s for L=5); the module documents this.

## Other design decisions

- The 3x4 transform's translation is `hinge + R * offset`, so the matrix places the block
  in world space; with hinge `[0,0,0]` it is exactly identity rotation plus the offset.
  `offset` is the block's minimum corner relative to the hinge point, so at angle 0 the
  model origin lands at the block's own corner.
- Collision checks only non-leaf blocks: the concept says solid blocks stop the trunk and
  the canopy passes through grass/flowers. Solid ground is found by flooring each rotated
  block centre to a `BlockPos`. The caller's `CollisionGrid` must exclude the felled tree's
  own blocks (they are removed with the cut).
- Collision is tested after each integration substep, so the stored `impact_angle_rad` can
  overshoot first contact by at most one substep (about 1–1.5°).
- The bounce is a single half-sine of 0.2 s reaching exactly `BOUNCE_DEG`, inside the 1 s
  delay; `BreakUp` begins 1 s after the first impact.
- `rest_angle_rad` is an extra `FallingTree` field (not in the task's field list); the
  `BreakUp` variant carries only `elapsed`, and the renderer still needs the settled angle.
- `impact_damage = min(|angular_vel| * |distance| * 2, 20)`, and 0 when disabled or when
  the input is not finite.
- `step` clamps `dt` to 0.25 s and splits it into 1/120 s substeps, so a stalled server
  tick cannot spin the integrator.

## Design decisions

- `decide_chop` checks in this order: permission, sneak, axe, scanned tree, durability.
  Permission is independent of config; sneak and axe honour their config switches.
- `axe_wear` consumes one roll per log when Unbreaking is present: the point is ignored
  when `roll < level / (level + 1)`, damaged otherwise. Rolls beyond `log_count` are
  unused; missing rolls count as damage, so a caller with no random source errs towards
  wearing the axe. Level 0 short-circuits to `log_count` wear.
- `decide_chop` uses that concrete wear against `remaining_durability`; creative mode skips
  both the wear and the durability check. `max_coverable_logs` is the expected budget
  (`durability * (level + 1)`) for the adapter/UI, not the felling decision.
- `chop_exhaustion` is `0.005 * log_count`; the time multiplier is `1 + logs / 10`, capped
  at 5, and the speed multiplier is its reciprocal.
- Break-up drops land at `hinge_center + rotate_offset(block.center_offset(), direction,
  tree.angle_rad())`, i.e. the settled angle at break-up.
- Logs merge into the first same-variant stack within `DROP_MERGE_RADIUS = 2.0` blocks of
  the stack's anchor (horizontal distance; height is ignored) that still has room, capped
  at `max_stack_size` (values below 1 act as 1). A full stack starts a new one.
- Each leaf block gets its own `DropStack` with `count: 1`, because the adapter evaluates
  its loot table per leaf.
- `plan_midfall_drops` drops every block at `tree.hinge_center()` with the same log merging,
  so a quit or chunk unload loses and duplicates nothing. It also emits the replant plan
  when `auto_replant_sapling` is on, matching the normal break-up path.
- `ReplantPlan.sapling_variant` is the tree's first log variant. Block ids stay opaque
  here; the adapter maps the log variant to its sapling, as with every other variant in
  this crate.

## Runtime (`runtime.rs`)

- `try_start_fall(world, cuts, ctx, config, wear_rolls, player)` scans with
  `scan_tree_with_cuts`, asks `decide_chop`, and on `FellTree` returns every log and leaf
  position for same-tick removal, the tool damage, the exhaustion and a new tree id. On a
  refusal it returns `VanillaSingleBlock` and leaves the runtime empty.
- The falling tree is built from the scan: hinge at the first cut, `trunk_height` from the
  highest log, direction away from `player`, one `FallingBlock` per log and leaf.
- `tick(dt, grid)` steps every active tree, reports `entered_falling`, `impacts` (with the
  hinge and speed) and `completed` trees with their `DropPlan`; a completed tree is removed.
- The camera shake impulse is 1.0 degree with a 0.5 s linear decay; it is applied only
  when that tree's `camera_shake` is on, and `camera_shake_offset` reports the current value.
- `collect_render_instances` emits, for every block of every active tree,
  `origin = hinge_center` and `transform_3x4 = block_transform_3x4([0,0,0], dir, angle,
  offset)`, i.e. a local transform ready for `ModelInstance::new(origin, transform, ...)`.
- `drain_all_midfall_drops` plans mid-fall drops for every active tree, clears them and
  returns the plans.

## Adapter decisions

- `break_block` scans the cut log, then clears every scanned log and leaf with the tree's
  air state and returns `Flow::Cancel`. Cancelling is deliberate: the tree's drops come
  from the runtime's plan later, so letting vanilla also drop the cut log would duplicate
  one item. Tool wear and exhaustion are applied by the adapter first.
- `player_break_speed` multiplies `new_speed` by `chop_speed_multiplier`, cached per
  level/position for one second (20 ticks), so mining does not scan every tick.
- `level_tick_post` (server side) ticks with `dt = 0.05`; solid collision comes from each
  block's collision shape (grass and flowers have none), entities within 8 blocks of the
  hinge take `impact_damage`, log stacks spawn from the plan, and a sapling is placed when
  `auto_replant_sapling` is on.
- `submit_custom_geometry` groups instances by variant, resolves
  `minecraft:block/<block name>` through `render_assets().model`, draws each batch with
  `draw_model_instances`, and evicts a stale model after a refused draw.
- Block names are recorded per opaque `u16` variant (FNV-1a over the name) so drops,
  replanting and models can be resolved from the pure runtime's variant.
- `server_stopping` drains mid-fall drops into the first loaded level.

# Fix Report — Tree Removal, Time Units and the `voxel-tree-fall.html` Animation

## Root causes of the stuck tree / stuck animation

1. **Tick/seconds mix-up.** `self.world.game_time` is in ticks (20/s), but the phases
   compared `now - since` against `WARNING_SECS = 0.5` / `BREAKUP_SECS = 1.0`. The whole
   state machine therefore ran in 0.5–1 tick and the animation was never visible.
2. **`*canceled = true` kept the cut log.** `game.rs:4157` returns `Ok(false)` before the
   normal break path when the hook cancels, and the canceled block is acknowledged back.
   Our clear list also excluded the cut position (`find_tree` removes the start), so the
   cut log stayed in the world and the trunk looked like it never fell.

## Fixes

- `runtime.rs` now tracks `elapsed_secs` on every `ActiveTree`: `+= 0.05` per server tick,
  and the renderer uses `elapsed_secs + partial * 0.05`, so the animation runs in real
  seconds and is smooth at any frame rate. `game_time` is no longer compared to seconds.
- `timber_fall_destroy_block` no longer sets `*canceled`; the cut log is left to vanilla,
  which removes and drops it normally. The rest of the tree is still cleared by
  `set_block(..., 3)` in the same tick, and the drop plan excludes the cut log, so there
  is no duplication. The built-in Falling Trees hook sees a cleared tree and returns.

## Reference animation (`voxel-tree-fall.html`, sound OFF)

`runtime.rs` now implements the exact default timeline: `duration = 3 s`, `IMPACT = 0.50`,
`BREAK = 0.66`, `LAST = 0.80`, `gravity = 14`, `bounce = 5°`, no overshoot, linear speed
curve.

- **Fall:** the `SHAPE` inverted-pendulum curve (`th = 0.08`, `w += sin(th) * 0.002`,
  `th += w * 0.002`, normalized) maps `p / IMPACT` onto `0..90°`; solid ground can lower
  `impact_angle` earlier.
- **Bounce:** `HOPS = [[0, 0.54, 1], [0.54, 0.30, 0.3], [0.84, 0.16, 0.09]]`, each
  `angle = impact_angle - 4u(1-u) * amp * 5°`.
- **Logs:** sorted base-to-tip; log `i` pops at `BREAK + (LAST-BREAK) * i / (n-1)`, with
  the 0.16 s `scale = 1 + 0.35w²` swell, then it is hidden and its own block drops spawn
  at its rotated landing position.
- **Leaves:** each leaf's break-off fraction is the earliest `p < IMPACT` where its
  rotated centre falls to `hinge_y + 0.55`; before that it rides the trunk, after it free-
  falls under gravity 14 with deterministic velocity/spin, shrinks after landing, and
  spawns its block drops when gone.
- **Completion:** at `p >= 1`, remaining drops are flushed, the axe wears for the felled
  logs, and the tree is removed. All `play_unshared` calls were removed (sound off).
- The hand-written render matrix now applies the reference angle, the per-log swell scale
  and the leaf fall/spin/shrink matrices, still through the verified
  `block_model_vertices(state, 42, …)` injection at `block_item_display_geometry`.

# Fix Report — `E0004`: Wildcard Arm for `#[non_exhaustive] HudMode` in `zoom/key.rs`

## Root cause

`mod_api::HudMode` (`crates/horizon-mod-vocab/src/client/hud_mode.rs`) is `#[non_exhaustive]`.
A match on it from another crate must carry a wildcard arm, so the HUD save in
`native-mods/zoom/mixins/zoom/key.rs` failed the game build:

   --> crates/horizon-client/src/game/starling/native_compat.rs:343:31

# Feature Report — Timber Fall: Smooth Fall + Dust Particles

## Smooth animation (`native-mods/timber_fall/mixins/timber_fall/runtime.rs`)

- **`smooth_secs` locked to the tick clock**: the render no longer accumulates its own frames
  (and no longer needs `last_render_at`, removed). It is now
  `smooth_secs = (elapsed_secs + last_tick_at.elapsed().min(TICK_SECS)).max(smooth_secs).min(DURATION)` —
  the tick's fraction extrapolated by wall clock, monotonic, so 60/120 FPS frames are silky, the
  clock never drifts from the server's, and a stalled server freezes the animation with the world.
- **Organic shape curve**: `shape_curve` now integrates from an initial push (`w = 0.3`, was 0.0),
  so the trunk leaves with a little of its own speed instead of hanging nearly still for ~0.8 s
  and then whipping down. Its seed also starts at the lean itself (`vec![th]`), which normalizes
  to exactly 0 instead of a negative first sample. The timeline is re-proportioned to a weighty
  fall: `DURATION = 2.4`, `IMPACT = 0.44`, `BREAK = 0.64` (`LAST` unchanged) — the fall itself is
  `IMPACT * DURATION ≈ 1.06 s`.
- **`impact_p: Option<f64>`** on `ActiveTree`: the tick records the fraction where
  `timber_fall_hits` first stops the trunk (and stops checking terrain after that). `tree_angle`
  bounces from there — the hop timeline is remapped `IMPACT + (p - q) * (BREAK - IMPACT)/(BREAK - q)`
  — so a trunk the ground caught early dips and settles immediately instead of freezing flat until
  `IMPACT` and then snapping into the bounce. `timber_fall_camera_shake` uses `impact_p` too, so
  the shake begins when the trunk actually lands. The thud sound already fired on that tick.

# Item Physics native mod (`native-mods/item_physics`)

## What was built

A new native mod that takes over the dropped-item draw when it is on: items
tumble in the air about three seeded axes, and on landing a flat item lies down
(`rotation_x = FRAC_PI_2`) and a block sits up, both on a yaw seeded by the
item id, resting flush on the surface (lift computed from the turned bounding
box, so no floating bob and no sinking). Off (default ON, `Enabled: ON / OFF`
in Options > Mods), vanilla's bob and spin run untouched.

- `native-mods/item_physics/mixins/item_physics/horizon-mixin.toml` — the
  bundle: `[[module]]` `item_physics` from `runtime.rs` into
  `crates/horizon-client/src/game.rs`, a cancellable `HEAD` injection on
  `horizon_client::game::item_draw::Game<'_>::dropped_item_geometry`, and
  `native_mods` / `native_settings` / `native_settings_click` HEAD injections.
- `mixins/item_physics/runtime.rs` — the pose math and settings (also the
  crate's library, for its 6 unit tests): `pose()`, `yaw()`, `tumble()`,
  `turned_y_range()`, `Settings`.
- `mixins/item_physics/dropped.rs` — the draw: mirrors `item_entity_geometry`
  call for call (range, frustum cull box, `resolve_item(…, DisplayContext::Ground, …)`
  via the real `owner_at`, `cluster_poses_with_depth`, packed light from the
  eye probe, entity culling with the posed envelope and `Bypass` when off,
  `submit_item_skinned`/`submit_item_world`, `mark_outline`, `abgr`,
  `finish_entity_occlusion`/`cull_skinned`), with the physics pose matrix
  `T(pos) · T(0, lift, 0) · R_y · R_z · R_x` in vanilla's frame.
- `mixins/item_physics/{list,settings,click}.rs` — the Mods-screen row and the
  settings page; settings kept in
  `horizon-mods/.horizon-mod-data/item_physics/enabled` (distant_horizons'
  thread-local + `native_set_setting` pattern).
- `Cargo.toml` (standalone workspace, `[lib] path = mixins/.../runtime.rs`),
  `compatibility.json` (hooks 1, same revisions as zoom), `LICENSE`, `README.md`.
- `.github/workflows/android.yml`: `item_physics` added to both the
  `native_mods` default and the fallback `MODS` string (yaml parses; both lines
  verified).

## The visibility question the task flagged

The task warned that `pub(super)` in `game/interface/item_draw.rs` would not be
visible from `crate::game::item_physics`. Checked against the source: area
folders are physical only — `game.rs` declares no `mod interface`, nothing in
the tree spells `crate::game::interface::`, and `game/mobs/mob_blocks.rs:674`
already calls item_draw's `pub(super)` `resolve_item` from another area. So
`pub(super)` there is `pub(in crate::game)` and every helper the draw needs is
reachable; only the private `dropped_item_cull_box` is replicated (byte-for-byte)
as `cull_box`, and `owner_at` is called directly instead of being replicated.
The injection target is spelled `horizon_client::game::item_draw::…` (module
path, like every existing `target =` in native-mods; there is no `interface::`
segment in Rust paths).

## Verification

The strongest check available on this box: a throwaway mock crate in `/tmp`
that `include!`s the **real** `dropped.rs` and `runtime.rs` verbatim against
mocks of every game/engine type they touch, with the real visibilities
(`pub(super)` methods on `Game` declared in area modules, `Dim` private in
`game.rs`, `crate::game::item_draw::owner_at`, `crate::game::entity_culling`).
It compiles clean and its 7th test drives the hook end to end: the mod takes
over (`ControlFlow::Break`) and draws. Reading it also caught two real bugs
before CI would have: the model translation is camera-relative (`pos`, as
vanilla's), and the `nether_lighting()` method is about dimension types, so the
draw uses vanilla's own `game.dim == Dim::Nether` condition.
