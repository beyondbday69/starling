## Design decisions to review

- `variant` is an opaque `u16` block id. Task 1 has no engine dependency, so the mapping from
  Horizon/Vanilla log block ids to these numbers belongs to the adapter task (Task 4). No
  Horizon API name is used or invented here.
- A log neighbour must match the cut log's `variant`, as the task says. Species is taken from
  the cut log.
- Counting leaves uses the natural-leaf blob reachable from the logs (max 6 blocks from the
  nearest log, at most 4096 leaves) rather than only directly adjacent ones. Player-placed
  (`persistent: true`) leaves are neither counted nor walked through, and a leaf must have the
  tree's species to count. This is what keeps a wooden house or a log pile out.
- Nether fungus: any `WartBlock` counts, regardless of its variant, and wart blocks are
  returned in `ScannedTree::leaves` because the render/fall step has to move the whole cap.
- Mangrove: `MangroveRoot` bridges two logs for mangrove trees only, one root block deep.
- Cherry: branches connect through the normal diagonal log rule; its leaves are collected by
  the same natural-leaf rule. No extra cherry-only rule beyond that is implemented.
- `scan_tree_with_cuts` is an addition to the listed surface. Without it a single
  `scan_tree(cut_pos)` call has no way to know whether the other three logs of a 2x2 base were
  cut, so `IncompleteTwoByTwo` would be unreachable. `scan_tree` keeps the exact signature the
  task specifies.

## Fall-time decision (`fall_speed`)

`fall_speed` scales **simulated time**, not angular acceleration: each real second advances
the fall by `fall_speed` simulated seconds. That is what the concept's "1.5x speed" column
means, and it reproduces its table. Verified before coding with the same integrator
(semi-implicit Euler, 1/120 s substep, start at 3°):

| L | realistic | 1.5x simulated | concept table |
| --- | --- | --- | --- |
| 5 | 2.417 s | 1.617 s | 1.6 s |
| 10 | 3.433 s | 2.283 s | 2.3 s |
| 20 | 4.850 s | 3.233 s | 3.2 s |
| 30 | 5.933 s | 3.950 s | 4.0 s |

Scaling `alpha` by `fall_speed` would only divide times by `sqrt(1.5) ≈ 1.225` and miss the
table (e.g. 1.97 s for L=5); the module documents this.

## Other design decisions

- The 3x4 transform's translation is `hinge + R * offset`, so the matrix places the block
  in world space; with hinge `[0,0,0]` it is exactly identity rotation plus the offset.
  `offset` is the block's minimum corner relative to the hinge point, so at angle 0 the
  model origin lands at the block's own corner.
- Collision checks only non-leaf blocks: the concept says solid blocks stop the trunk and
  the canopy passes through grass/flowers. Solid ground is found by flooring each rotated
  block centre to a `BlockPos`. The caller's `CollisionGrid` must exclude the felled tree's
  own blocks (they are removed with the cut).
- Collision is tested after each integration substep, so the stored `impact_angle_rad` can
  overshoot first contact by at most one substep (about 1–1.5°).
- The bounce is a single half-sine of 0.2 s reaching exactly `BOUNCE_DEG`, inside the 1 s
  delay; `BreakUp` begins 1 s after the first impact.
- `rest_angle_rad` is an extra `FallingTree` field (not in the task's field list); the
  `BreakUp` variant carries only `elapsed`, and the renderer still needs the settled angle.
- `impact_damage = min(|angular_vel| * |distance| * 2, 20)`, and 0 when disabled or when
  the input is not finite.
- `step` clamps `dt` to 0.25 s and splits it into 1/120 s substeps, so a stalled server
  tick cannot spin the integrator.

## Design decisions

- `decide_chop` checks in this order: permission, sneak, axe, scanned tree, durability.
  Permission is independent of config; sneak and axe honour their config switches.
- `axe_wear` consumes one roll per log when Unbreaking is present: the point is ignored
  when `roll < level / (level + 1)`, damaged otherwise. Rolls beyond `log_count` are
  unused; missing rolls count as damage, so a caller with no random source errs towards
  wearing the axe. Level 0 short-circuits to `log_count` wear.
- `decide_chop` uses that concrete wear against `remaining_durability`; creative mode skips
  both the wear and the durability check. `max_coverable_logs` is the expected budget
  (`durability * (level + 1)`) for the adapter/UI, not the felling decision.
- `chop_exhaustion` is `0.005 * log_count`; the time multiplier is `1 + logs / 10`, capped
  at 5, and the speed multiplier is its reciprocal.
- Break-up drops land at `hinge_center + rotate_offset(block.center_offset(), direction,
  tree.angle_rad())`, i.e. the settled angle at break-up.
- Logs merge into the first same-variant stack within `DROP_MERGE_RADIUS = 2.0` blocks of
  the stack's anchor (horizontal distance; height is ignored) that still has room, capped
  at `max_stack_size` (values below 1 act as 1). A full stack starts a new one.
- Each leaf block gets its own `DropStack` with `count: 1`, because the adapter evaluates
  its loot table per leaf.
- `plan_midfall_drops` drops every block at `tree.hinge_center()` with the same log merging,
  so a quit or chunk unload loses and duplicates nothing. It also emits the replant plan
  when `auto_replant_sapling` is on, matching the normal break-up path.
- `ReplantPlan.sapling_variant` is the tree's first log variant. Block ids stay opaque
  here; the adapter maps the log variant to its sapling, as with every other variant in
  this crate.

## Runtime (`runtime.rs`)

- `try_start_fall(world, cuts, ctx, config, wear_rolls, player)` scans with
  `scan_tree_with_cuts`, asks `decide_chop`, and on `FellTree` returns every log and leaf
  position for same-tick removal, the tool damage, the exhaustion and a new tree id. On a
  refusal it returns `VanillaSingleBlock` and leaves the runtime empty.
- The falling tree is built from the scan: hinge at the first cut, `trunk_height` from the
  highest log, direction away from `player`, one `FallingBlock` per log and leaf.
- `tick(dt, grid)` steps every active tree, reports `entered_falling`, `impacts` (with the
  hinge and speed) and `completed` trees with their `DropPlan`; a completed tree is removed.
- The camera shake impulse is 1.0 degree with a 0.5 s linear decay; it is applied only
  when that tree's `camera_shake` is on, and `camera_shake_offset` reports the current value.
- `collect_render_instances` emits, for every block of every active tree,
  `origin = hinge_center` and `transform_3x4 = block_transform_3x4([0,0,0], dir, angle,
  offset)`, i.e. a local transform ready for `ModelInstance::new(origin, transform, ...)`.
- `drain_all_midfall_drops` plans mid-fall drops for every active tree, clears them and
  returns the plans.

## Adapter decisions

- `break_block` scans the cut log, then clears every scanned log and leaf with the tree's
  air state and returns `Flow::Cancel`. Cancelling is deliberate: the tree's drops come
  from the runtime's plan later, so letting vanilla also drop the cut log would duplicate
  one item. Tool wear and exhaustion are applied by the adapter first.
- `player_break_speed` multiplies `new_speed` by `chop_speed_multiplier`, cached per
  level/position for one second (20 ticks), so mining does not scan every tick.
- `level_tick_post` (server side) ticks with `dt = 0.05`; solid collision comes from each
  block's collision shape (grass and flowers have none), entities within 8 blocks of the
  hinge take `impact_damage`, log stacks spawn from the plan, and a sapling is placed when
  `auto_replant_sapling` is on.
- `submit_custom_geometry` groups instances by variant, resolves
  `minecraft:block/<block name>` through `render_assets().model`, draws each batch with
  `draw_model_instances`, and evicts a stale model after a refused draw.
- Block names are recorded per opaque `u16` variant (FNV-1a over the name) so drops,
  replanting and models can be resolved from the pure runtime's variant.
- `server_stopping` drains mid-fall drops into the first loaded level.
